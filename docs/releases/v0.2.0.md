# CryptoDesk AI v0.2.0

**Status:** Release candidate — prepared for Tech Lead review; not tagged,
published, or deployed.

This release candidate is a validated incremental development release after
the `v0.1.0-mvp` source release (`3187746aea5afa5f51acfe3d0f0f763cbf6b46a5`).
It does not rewrite or move that historical tag.

## Implemented

- Static, read-only MVP application routes for overview, Market, News,
  Portfolio, and Morning Meeting.
- Provider-neutral Federation with Market, News, and Portfolio federation and
  deterministic cross-domain Intelligence Composition. Observations retain
  provenance, freshness, availability, disagreement, and domain-local authority.
- Public Developer Quick Start and four executable local examples.
- GitHub issue forms, pull-request guidance, security reporting, Code of
  Conduct, and enabled Discussions.
- Technical Paper Public Edition and conservative Public Launch Package drafts.
- Dependency-free `@cryptodesk-ai/observability` contracts for bounded logs,
  health observations, metrics, failures, and correlation metadata.
- Deterministic offline performance baseline for Federation and Market paths.
- Security Hardening audit with no actionable vulnerability found.
- Dependency-free `@cryptodesk-ai/community-feedback` records with exactly four
  explicit categories: bug, ux, architecture, and feature_request.

## Authority and safety boundaries

Market, News, Portfolio, and Morning Meeting retain their established
deterministic/canonical ownership. Federation qualifies observations but does
not select winners or create consensus. Intelligence Composition is
non-canonical composition only. AI remains non-authoritative:

```text
untrusted_model_execution
→ untrusted_candidate_interpretation
→ non_authoritative_interpretation
```

Runtime Safety remains bounded:

```text
explicit request
→ candidate
→ explicit authorization
→ single-attempt permission
→ at-most-one execution
→ terminal result
→ stop
```

## Not implemented

This release does not provide autonomous research, planning, trading,
recommendations, custody, wallet or private-key handling, asset transfer,
self-starting loops, provider selection/fallback/consensus, monitoring
backends, distributed tracing, persistent telemetry, or scalability/SLA
guarantees. Community feedback is advisory and never changes the roadmap or
implementation automatically.
